# Responsive guidance experiment protocol

## Question

Does a short responsive composition example on existing Table/Tabs usage pages reduce
implementation/CSS inspection and completed authoring cost for a directory task?

The saved-trace audit found implementation reads in all six library directory attempts
across the bundled and pointer studies. Existing pages already describe state, sorting,
filtering, and keyboard responsibilities. CSS queries suggest an unresolved composition
question, but author motives are mostly unknown. This is a hypothesis, not an established cause.

## Conditions and scope

Nine fresh attempts, one directory task, three conditions, three repetitions:

- React/CSS without a component library.
- Bundled usage pages plus the previously tested declaration pointers.
- The identical package with responsive supplements on only Table and Tabs usage pages.

Condition order rotates native/control/layout, control/layout/native, layout/native/control.
Internal agent names are neutral sample_01 through sample_09. Prompts identify the installed
library where applicable, but contain no guidance paths, variant names, or reading advice.
Reuse the preceding directory brief and app scaffold. All original runtime, declarations,
metadata, index, 85 prop references, full contracts, and minimal examples remain unchanged.
No README, AGENTS, public API, production code, source-file comments, or export changes.

The supplement demonstrates application-owned wrappers using ordinary HTML/CSS. It does not
make internal DOM selectors into supported styling hooks. Inventory example content differs
from the evaluated people directory. No complete solution to the task is supplied.

## Freeze and checks

Before authoring, freeze this protocol, supplement/preparation source, existing task/checker
source, each package tree, and actual assignment/prompt hashes. Verify that exactly two usage
pages differ, original page text remains intact around the insertions, and runtime/declaration
trees match byte for byte. Compile the supplemental JSX and exercise its responsive layout
at 390px and 1280px. Record preflight results before launching authors.

Authors are fresh gpt-6.1-sol/high contexts, with no parent-history fork. Their only writable
files are their fixture's src/app.tsx and src/styles.css. No Git mutations, delegation, network,
browser self-checks, other fixtures, source repositories, or test modifications. Each author
runs the same TypeScript/build check. All inherited instruction costs stay in author totals.

Independent T3 interactions reuse the frozen directory checker and established transport
adapter. Forty-eight assertions per app at 390px and 1280px, 432 primary assertions overall.
Capture initial sources, traces, and costs before repair. If repairs are needed, record initial
failures, use narrowly targeted follow-ups, and include all repair costs. Preserve tool errors
and interrupted checks separately. Do not discard or rerun authors because of their read route.

## Measures and interpretation

Primary measures: completed total input plus output, uncached input plus output, and correctness.
Also record actual supplement uptake, runtime and stylesheet reads, tool requests/output,
app/CSS size, and active author time. A requested path or filename alone is not content uptake.
Report every attempt and matched repetition, not just aggregates. Cached input is a subset of
input; reasoning is a subset of output. Uncached input plus output is a diagnostic, not a price.
Coordinator setup, audit, evaluation, and analysis are excluded from author totals.

Stop after all nine completed attempts and initial/final independent checks. Interpret this
as a small task-specific pilot. It cannot establish general savings, isolate which supplement
sentence matters, prove an agent's reason for a read, or justify production adoption. Keep
the earlier studies as context, not additional controls. Present measured findings for review.

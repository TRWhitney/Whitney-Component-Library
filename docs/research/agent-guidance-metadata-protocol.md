# Metadata experiment protocol

## Question and authorization

Does omitting author-tooling fields from installed package metadata reduce completed agent
authoring cost without reducing correctness? Whitney authorized this bounded next experiment
with "Alright, lets do that next." The prior integration remains uncommitted for review.

## Conditions

Six fresh directory attempts, three repetitions, two conditions. The full package uses the
current local guidance integration. The trimmed package differs only in package.json, omitting
scripts and devDependencies. Retain every other field, all package files, four public exports,
85 usage pages/full references/props closures, and the Table/Tabs layout supplements.
No native condition is added; previous native results are historical context only.

Order by repetition is full/trimmed, trimmed/full, full/trimmed. Agent names are neutral
attempt_01 through attempt_06 and assignments contain no condition, metadata, or guidance hints.
Reuse the preceding directory brief and scaffold, including the same app/data and required check.
Fresh gpt-6.1-sol/high contexts receive no parent-history fork. Freeze actual assignments, prompt
hashes, package trees, source/protocol hashes, and preparation/preflight evidence before authors.

Authors inspect only their app and installed dependencies. Only src/app.tsx and src/styles.css
are writable. No Git mutations, delegation, network, source repositories, other fixtures, test
changes, or browser self-checks. Inherited instruction costs remain in author totals.

## Preflight and evaluation

Pack and clean-install both variants. Verify metadata differs by exactly the two omitted fields,
all other installed package files match, guidance links/props/examples compile, and a consumer
production build succeeds. Use the same React 19 version/tooling as the author scaffold.

Reuse the frozen independent directory browser checker, 48 assertions per app at 390px and
1280px, 288 primary assertions total. Use T3 collaborative browser interactions and the previously
recorded transport adapter. Preserve partial tool failures separately. Its narrow recovery
accepts a reported click failure only when a separate DOM read confirms the exact requested
postcondition. Assertions and consumer source remain unchanged by evaluation.

Capture initial app sources, completed traces, model/effort, and counters before repairs.
For failed app assertions, issue only a targeted repair in the same author context. Retain initial
failures and include every repair cost in completed totals. Authors who take different reading
routes are retained. Stop after six completed attempts and their initial/final checks.

## Measures and limits

Primary measures are completed input plus output, uncached input plus output, and correctness.
Record whole metadata/index/declaration reads, usage uptake, runtime/CSS inspection, failed reads,
build failures, tool requests/output, source size, active author time, and every matched repetition.
Content returned by tools proves reading; filenames or requested paths alone do not.
Use o200k_base for reference/output estimates, distinguish them from provider counters, and
preserve trace/source/assignment hashes. Cached input is a subset of input; reasoning is a subset
of output. Uncached input plus output is a diagnostic, not a price. Coordinator preparation,
package preflight, evaluation, capture, and analysis are excluded from author totals.

Require no quality regression and inspect each repetition before suggesting savings. This small
single-task pilot cannot establish general agent savings or improvement over native React/CSS.
No production metadata change, adoption, commit, publishing, README/AGENTS edit, API change,
declaration restructuring, or additional author trial is included.

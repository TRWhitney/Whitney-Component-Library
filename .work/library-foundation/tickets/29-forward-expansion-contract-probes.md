# 29 Forward-Expansion Contract Probes

**What to build:** Non-production interface models and focused probes that challenge the shared
foundation against future large collections, virtualization, advanced composition, and other
mapped behavior without expanding the stable catalog.

**Blocked by:** [Operational Workflow Prerelease](18-operational-workflow-prerelease.md),
[Data Analysis Prerelease](23-data-analysis-prerelease.md), [Markdown Authoring Prerelease](27-markdown-authoring-prerelease.md),
[Application Workbench Prerelease](28-application-workbench-prerelease.md)

**Status:** blocked

- [ ] Every component family in the accepted expansion map is represented by production behavior
  or an explicit probe.
- [ ] Large or virtualized collection models challenge stable key, focus, selection, loading, and
  public state conventions without leaking a virtualization engine.
- [ ] Compound-control and advanced-composition probes challenge slots, callbacks, events, and
  controlled/uncontrolled conventions without creating a universal prop surface.
- [ ] Localization, right-to-left, server rendering, hydration, form, pending, validation, and
  extension conventions are assessed across materially different families.
- [ ] Findings identify whether any accepted public API assumption must return to planning before
  compatibility stabilizes.
- [ ] Probe code is clearly isolated from production exports and disposable results are removed.
- [ ] Durable findings are recorded once and linked from affected contracts or decisions.
